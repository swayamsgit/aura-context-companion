Local context cards and evidence drafts work without a model. The optional Node backend calls Meta Model API and validates that each output uses exact original event text and a valid source ID. Invalid or rewritten facts are rejected. This simple validation is not clinical validation.

Built in this prototype

  • People/context cards with manual identity selection
  • Daily event capture, selection and removal
  • Browser-local storage with clear/reset controls
  • Evidence-linked draft and review-before-copy gate
  • Meta Model API backend adapter, consent gate and request cap
  • Input validation and automated tests

Not built or validated

  • Ray-Ban capture, Bluetooth streaming or mobile deployment
  • On-device Llama / ExecuTorch inference
  • Face, confusion, emotion or clinical-state detection
  • Medication advice or emergency monitoring
  • Encrypted database, end-to-end encryption or clinical privacy compliance
  • WhatsApp API delivery or scheduled caregiver messages

Privacy, honestly

Notes in this demo are stored in this browser, unencrypted. They can be lost when browser storage is cleared and are not synced. Live Meta requests transmit the selected event text to Meta. This prototype is not a medical device and should not be used with real patient data, for treatment, for emergencies, or to decide whether someone is safe alone.

The original vision

The longer-term Aura concept pairs wearable input, on-device memory support and a caregiver loop. Those are design directions only. Hardware access, model performance, clinical suitability, consent, privacy controls and regulatory requirements would each need separate validation before real-world use.
